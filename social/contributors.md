# Contributors and credits

MForce Enhanced Framework is maintained as an open-source project in
[GotUrBack-Public/MForce-Enhanced-Framework](https://github.com/GotUrBack-Public/MForce-Enhanced-Framework).
Contributions are welcome from developers, testers, designers, technical
writers, translators, accessibility reviewers and responsible security researchers.

## Project ownership and attribution

- **Repository / project organization:** [GotUrBack-Public](https://github.com/GotUrBack-Public).
- **Copyright notice in the MIT license:** GotUrBack04 (2026). The
  [LICENSE](../LICENSE) is the authoritative copyright notice.
- **Original architecture inspiration:** [MidnightCoding1/mForce](https://github.com/MidnightCoding1/mForce).
  This project describes itself as a rebuild of that original architecture.
  The upstream project is credited for provenance, not represented as an
  official maintainer or sponsor of this repository.

## Community contributors

For an accurate, continuously updated list of people who contributed code,
documentation or other Git-tracked changes, see:

**[GitHub contributors](https://github.com/GotUrBack-Public/MForce-Enhanced-Framework/graphs/contributors)**

Pull-request authorship and Git history are the source of truth. We do not
invent contributor names or assign credit to accounts without evidence.

Contributions that do not appear in Git history (for example private bug
reports, design feedback or translation review) may be acknowledged with
the contributor's **explicit consent**. Security reporters can opt out of
public recognition. Contact the maintainers through an issue for a
non-sensitive credit correction; use [SECURITY.md](../SECURITY.md) for
confidential disclosures.

## Ways to contribute

| Area | Useful contributions |
| --- | --- |
| Termux / Linux | Device testing, compatibility fixes, packaging |
| Bash / Python | Bug fixes, bounded modules, error handling, unit tests |
| Website | Responsive design, reduced-motion support, accessibility |
| Documentation | Accurate tutorials, command examples, translations |
| Privacy | Data-flow reviews, redaction, retention guidance |
| Security | Responsible vulnerability reporting and scoped test cases |

Read [How to contribute](how_to_contribute.md),
[Code of Conduct](../CODE_OF_CONDUCT.md) and
[AI usage transparency](ai_usage.txt) before submitting a change.

## Credit principles

We credit substantive human contributions, preserve copyright and license
notices, and do not equate AI-assisted text generation with a human contributor.
No contribution or credit guarantees merge approval, employment, compensation
or a security-bounty payout.
